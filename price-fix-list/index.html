Product price in schema: the 49 products to correct

OPEN, FOR PAULOChecked live Oct 13, 2026. Saiaf promised this list in the Oct 11 meeting, so Paulo does not have to guess. 49 products still send Google the wrong main price.

In short

What is wrong
On these products the single offers.price in the Product schema is the price of the first lease term in the list. It must be the daily price.
The pattern
48 of the 49 have a daily term that is not first in the list; the code takes the first term. One product, 2674, has no daily term and shows its monthly price (4,500) instead of its lowest price (350 per hour). On the other 1,000 products the right term is first, so they are already correct.
The fix
Do not take the first term. Search the terms for the daily one and use its price. If a product has no daily term, use the lowest price.
Do not change
The priceSpecification entries are correct on all of these. Keep them.
Done when
Every row below shows the value in the last column. TMD re-runs the check on all products.

The rule in code

const terms = product.post_lease_terms.filter((t) => t.type === "available");
const daily = terms.find((t) => t.lease_term === "daily");
const mainPrice = daily
  ? Number(daily.price)
  : Math.min(...terms.map((t) => Number(t.price)));
// offers.price = mainPrice

Field names follow the June copy of the API query (post_lease_terms, lease_term, type). Adjust them if the live names differ.
