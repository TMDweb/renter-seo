02

Why these faults are important

Users see the Open Graph fault most frequently. Renter gets new users from WhatsApp and from social media. At this time, a shared link shows only the URL. It shows no image and no text. A card with the item and the price gets more clicks than a plain URL. This fault has a direct effect on the Haraj and WhatsApp work.

Structured data gives results that Renter does not get now. The site has no Product schema and no Offer schema. Thus Google cannot show the price or the availability in the search results. AI search tools also cannot read the data correctly. On Aug 5 the Merchant Center feed had 1,036 products. Thus the page has the data that the schema needs.

The redirect fault has an effect on the most traffic. 57% of the clicks from search go to a URL with no language prefix. Each of these URLs returns 307. A 307 tells Google that the change is temporary. Thus Google keeps the ranking signals on that URL. Google does not move them to the Arabic page or to the English page that shows the content. Change the status to 301 and Google will move the signals.

Make the canonical URL absolute, as you did for hreflang. The Google documentation asks for full URLs. You made the hreflang URLs absolute after Jul 26. The canonical URL is still relative. Thus the two types of URL in the same <head> are not the same.

04

Fix 1 and 2: Open Graph and Twitter Card tags

Scope: all 2,280 pages. Zero pages have these tags now. One template change corrects all the pages.

Add these tags to the shared metadata of each route. Use the data that the page has already. In the Next.js App Router, use the openGraph key and the twitter key of the Metadata object. You can set them one time in the root layout. Then you can change them for each route.

Product pages, using existing listing fields:

<meta property="og:type"        content="product" />
<meta property="og:site_name"   content="Renter" />
<meta property="og:locale"      content="ar_SA" />   <!-- en_US on /en/ -->
<meta property="og:title"       content="{page title}" />
<meta property="og:description" content="{meta description}" />
<meta property="og:url"         content="https://renter.net{path}" />
<meta property="og:image"       content="https://renter.net{first listing image}" />
<meta property="og:image:width"  content="1200" />
<meta property="og:image:height" content="630" />

<meta name="twitter:card"        content="summary_large_image" />
<meta name="twitter:title"       content="{page title}" />
<meta name="twitter:description" content="{meta description}" />
<meta name="twitter:image"       content="https://renter.net{first listing image}" />

Notes about how the card shows:

  • Make og:image an absolute URL. WhatsApp and Facebook cannot read a relative path.
  • Use one default image for the site. Some pages have no photo: the info pages, the category pages, and approximately 67 old listings with bad images. The default image prevents an empty card.
  • Make each image 1200x630 or larger. Also make each file smaller than approximately 300 KB. WhatsApp frequently shows no card for a larger file.

Fix 3: structured data (JSON-LD)

Scope: all 2,280 pages. Add Product and Offer to the 2,072 product pages. Add Organization and WebSite to the 2 home pages. Add BreadcrumbList to the 194 category and subcategory pages.

Zero JSON-LD blocks exist today. Minimum useful set:

  • Product pages: add Product. Put an Offer in it. The Offer must have price, priceCurrency: "SAR", availability and url.
  • Home page: add Organization with the legal name, the logo and the contact data. Also add WebSite with SearchAction.
  • Category pages and subcategory pages: add BreadcrumbList.
  • FAQ page: FAQPage.
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "{listing title}",
  "description": "{meta description}",
  "image": ["https://renter.net{listing image}"],
  "url": "https://renter.net{path}",
  "offers": {
    "@type": "Offer",
    "price": "{price}",
    "priceCurrency": "SAR",
    "availability": "https://schema.org/InStock",
    "url": "https://renter.net{path}"
  }
}
</script>

Caution. Add price only if the product has a true price. Some listings have 0 SAR or 1 SAR. These are not true prices. Do not put these values in the schema. If there is no true price, do not add the Offer block.

<link rel="canonical" href="/ar/properties/apartments/"/>      <!-- still relative -->

Fix 5: Change the redirects from 307 to 301. Do this fix first.

Scope: all URLs that have no language prefix. There are approximately 1,140. That is one URL for each page in the sitemap. The URLs in the table below and the 45 URLs in the sheet are examples only. They are the URLs that got clicks, thus they show the value of this fix. One change in the middleware corrects all of them.

A 307 status tells Google that the change is temporary. Thus Google keeps the URL with no language prefix in its index. Google does not move the signals to the language page. These redirects are permanent. Thus they must return 301. Note: /ar and /en without the last slash return 308. That is correct. Change only the language-prefix redirect in the middleware.

The size of this fault. TMD measured it in Google Search Console on Aug 5. TMD examined each page that got a click in the last 28 days. The URLs with no language prefix got 270 of 476 clicks. This is 57%. They also got 36% of the times that Google showed a page. 45 of these URLs got a click. All 45 return 307. There are no exceptions. The two pages with the most clicks on the site are on this path: renter.net/ with 97 clicks and /product/1228/myny-bystwn-ayjar-ywmy-wasbway/ with 63 clicks. Thus this fix is the most important one in the ticket. More than half of the traffic from search goes to a URL that keeps its ranking signals. Google does not move those signals to the page that shows the content.

08

Bonus fix, in the same template: the meta descriptions have two encodings

Scope: approximately 800 product pages. TMD tested a random sample of 60 product pages on Aug 5. 24 of the 60 have this fault. This is 40%. The site has 2,072 product pages. The examples in the sheet are 24 URLs only. One template change corrects all the pages.

The template encodes the HTML entities two times. Thus the entity text shows in the tag. The character does not show. Example:

# /en/product/2168/sony-fx30/
<meta name="description" content="كميرا سوني fx30&amp;nbsp;">
                                                  ^^^^^^^^^^ renders as literal "&nbsp;"

# /en/product/1560/kryn50tn/  → &amp;quot; instead of a quote mark

Encode the entity one time only. This fault is also the cause of the unwanted characters in some descriptions in the search results.
