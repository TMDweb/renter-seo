Rules, verified against the documentation. Apply all of them so nothing comes back later:

  • Eligibility scope: rental pages qualify for Google product snippets, not merchant listings (merchant listings require a purchase page). So hasMerchantReturnPolicy and shippingDetails stay out; they are merchant-listing fields. (merchant-listing doc)
  • price: emit a JSON number. The API gives the price as a string ("200"); cast it. Keep offers.price AND the priceSpecification entry; Google requires price or priceSpecification.price, and keeping both is valid. (product-snippet doc)
  • availability: map the API field availability_status: AVAILABLE → https://schema.org/InStock, UNAVAILABLE → https://schema.org/OutOfStock. Never drop offers; with zero reviews, offers is the property that keeps the block eligible.
  • Lease terms (post_lease_terms[].lease_term): one UnitPriceSpecification per available term, with the UN/CEFACT code: hourly → HUR, daily → DAY, weekly → WEE, monthly → MON. A fixed term gets no UnitPriceSpecification. offers.price = the daily price when a daily term exists, else the lowest-priced term. (schema.org/unitCode)
  • Reviews: when review_summary.review_count ≥ 1, add aggregateRating (ratingValue + reviewCount; bestRating defaults to 5) and the review array exactly as in 3b. author MUST be an object {"@type": "Person", "name": "…"}; a bare string fails validation. Only mark up reviews that are visible on the page and written by real users. When the count is 0, omit both. (review-snippet doc)
  • Deliberately omitted; do not add: brand and gtin (no source field in the API; never derive a brand from the title text) and priceValidUntil (a date that slips into the past suppresses the snippet).
  • Images: admin-production.renter.net is crawlable (its robots.txt blocks only /login; verified Aug 24). When a product has several photos, list them all in the image array.

Dev action C · how to render these blocks in Next.js · verified vs nextjs.org Aug 24

renter.net runs the Next.js App Router (the HTML carries self.__next_f flight data). The official Next.js JSON-LD pattern, so the blocks are correct, safe, and always in the server HTML:

  • Render in the server component (page.tsx or layout.tsx), as a native <script> in the returned JSX. Not next/script, not the metadata export (it cannot emit JSON-LD), and never from a client component or useEffect: Google warns that script-injected markup makes price and availability crawls less reliable. The block must be visible in view-source with JavaScript off.
  • Escape exactly as the Next.js docs show, in one shared helper used by every page type: 
    <script
  type="application/ld+json"
  dangerouslySetInnerHTML={{
    __html: JSON.stringify(jsonLd).replace(/</g, '\u003c'),
  }}
/>
    The \u003c replacement closes the </script> breakout hole. Do not escape anything else; Arabic stays raw UTF-8.
  • Build the object conditionally. JSON.stringify drops undefined properties (safe) but serializes null (fails validation). Spread optional parts: ...(count > 0 && { aggregateRating }). Guard against NaN from price math; it serializes to null.
  • Clean strings on the server before stringify: strip tags, decode entities (&nbsp; etc.), collapse whitespace. This is the same rule as the description fault in action A.
  • Optional: type the objects with the schema-dts package (WithContext<Product>) to catch wrong property names at compile time.

Definition of done, all four: (1) view-source with JavaScript disabled shows the correct block on each of the 12 test URLs; (2) the Rich Results Test passes each URL with zero errors; (3) validator.schema.org reports no errors; (4) no null values anywhere in the output. Reference: nextjs.org JSON-LD guide, Google on JavaScript-generated structured data.

Expectations, settled by the doc review so nobody chases them later: FAQ markup earns no rich result for Renter (Google limited that feature to government and health sites in 2023); the category ItemList earns no carousel (that feature covers courses, movies, recipes, restaurants only); the sitelinks search box was retired in Nov 2024. All three stay in the template because they are valid, cost nothing, and feed AI crawlers; expect no visual change in Google from them. The wins Google can show are the product snippet (price, availability, stars once reviews exist), the site name, the logo, and breadcrumbs.

02

Why these faults are important

  • Redirects (biggest): 59.4% of all search clicks land on a 307 URL, so Google holds the ranking signals there instead of passing them to the real page.
  • Open Graph: without it a shared link shows no image and no title. Renter grows through WhatsApp and social. Done Aug 10.
  • Structured data: without it Google cannot show price or availability, and AI search tools cannot read the products.
  • Canonical: Google asks for absolute URLs. hreflang is absolute; canonical in the same <head> is not.

Fix 1 and 2: Open Graph and Twitter Card tags

Done Aug 10. Verified on all 12 test pages, with absolute image URLs. Kept for reference.

Add these tags to the shared metadata of each route. Use the data that the page has already. In the Next.js App Router, use the openGraph key and the twitter key of the Metadata object. You can set them one time in the root layout. Then you can change them for each route.

Product pages, using existing listing fields:

<meta property="og:type"        content="product" />
<meta property="og:site_name"   content="Renter" />
<meta property="og:locale"      content="ar_SA" />   <!-- en_US on /en/ -->
<meta property="og:title"       content="{page title}" />
<meta property="og:description" content="{meta description}" />
<meta property="og:url"         content="https://renter.net{path}" />
<meta property="og:image"       content="https://renter.net{first listing image}" />
<meta property="og:image:width"  content="1200" />
<meta property="og:image:height" content="630" />

<meta name="twitter:card"        content="summary_large_image" />
<meta name="twitter:title"       content="{page title}" />
<meta name="twitter:description" content="{meta description}" />
<meta name="twitter:image"       content="https://renter.net{first listing image}" />

Notes about how the card shows:

  • Make og:image an absolute URL. WhatsApp and Facebook cannot read a relative path.
  • Use one default image for the site. Some pages have no photo: the info pages, the category pages, and approximately 67 old listings with bad images. The default image prevents an empty card.
  • Make each image 1200x630 or larger. Also make each file smaller than approximately 300 KB. WhatsApp frequently shows no card for a larger file.

Dev action (Aug 23): the four fields to correct on this block, with the complete corrected code, are at the top of the page under Open dev actions · A.

UPPERCASE values map to these fields, verified in the page's own data payload on Aug 10:

TokenField
PRODUCT_TITLEtitle
PLAIN_TEXT_DESCRIPTIONdescription, tags stripped, entities decoded
ABSOLUTE_IMAGE_URLSpost_images[].image
LISTING_IDid

PRICE_NUMBERpost_lease_terms[].price, as a number. If the listing has more than one lease term, use the one the page shows as its price
RENTAL_UNITpost_lease_terms[].lease_term → daily = "DAY" (verified), hourly = "HUR", weekly = "WEE", monthly = "MON"

Rules:

  • availability: availability_status AVAILABLE → https://schema.org/InStock; UNAVAILABLE → https://schema.org/OutOfStock. Keep offers in both cases; offers is what makes the block eligible when there are no reviews.
  • RENTAL_UNIT from the listing's rental period: hour "HUR", day "DAY", week "WEE", month "MON".
  • Price 0 or 1 SAR is a placeholder → remove offers.
  • Zero reviews → remove aggregateRating and review. One real review is enough to keep them (agreed Aug 10). Never invent a review. List every review in the array.
  • No hasMerchantReturnPolicy: Google requires it nowhere and recommends it only for purchase listings. Rentals end with the item coming back; Renter has a cancellation policy, and Google has no product field for that. Omit it.

  "url": FULL_LISTING_URL,

    "url": FULL_LISTING_URL,
    "priceCurrency": "SAR",
    "price": PRICE_NUMBER,
