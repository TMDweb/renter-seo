Head metadata layer: no Open Graph, no Twitter Cards, no structured data, relative canonical URLs, and temporary redirects carrying 57% of search clicks

Five systemic issues in the shared <head> template and routing layer. Each one is a single fix that applies to every page on the site, unlike the per-URL content fixes sent separately in the three issue sheets. Verified on 12 live URLs covering every page type on Jul 26, and re-verified on the same 12 on Aug 5. The hreflang item has been fixed since the first version and is marked as done below.

Priority: High (SEO + social) Area: Next.js metadata / head template, middleware Status: Open Reported: Jul 26, 2026
01

Summary

Every page on renter.net renders a <head> with a title, a meta description, a canonical and hreflang. What it never renders is Open Graph, Twitter Card, or structured data, and the canonical URL it does render is relative rather than absolute. Locale-less paths also redirect with a temporary status instead of a permanent one.

Updated Aug 5. This ticket was written on Jul 26 and every item was re-checked against production on Aug 5 before sending. One item has since been fixed and is marked as such: hreflang URLs are now absolute. Two items were added: the two home pages emit no hreflang at all, and Search Console now shows how much traffic the 307 redirects are holding up.

These are template-level, so each is one code change that fixes the whole site at once. That is the reason they are grouped in a single ticket rather than filed per URL.

The five issues
  1. No Open Graph tags anywhere, so shared links render with no image, title or description.
  2. No Twitter Card tags anywhere.
  3. No structured data (zero JSON-LD blocks), so no product rich results are possible.
  4. Canonical uses relative URLs, and the two home pages emit no hreflang at all. (The hreflang URLs elsewhere were made absolute after Jul 26 and are now correct.)
  5. Locale-less URLs redirect 307 (temporary) instead of 301, so ranking signals are not consolidated. This one now carries 57% of the site's search clicks, see section 07.
02

Why this matters

Sharing is the most visible one. Renter's growth motion is WhatsApp and social. Right now every shared listing link appears as a bare URL with no preview image or text, which measurably lowers click-through compared with a card that shows the item and its price. This affects the Haraj and WhatsApp outreach directly.

Structured data is the missed opportunity. A rental marketplace with no Product or Offer schema cannot show price or availability in search results, and cannot be read reliably by AI search surfaces. 1,036 products are already in the Merchant Center feed as of Aug 5, so the data needed to emit schema already exists in the page.

The redirects are the biggest one by traffic. 57% of every search click the site earns lands on a locale-less address that answers 307. Until that is 301, the ranking credit those addresses have built stays parked on a URL Google treats as provisional instead of consolidating onto the Arabic and English pages that actually serve the content.

Canonical needs the same absolute treatment hreflang just got. Google's documentation asks for fully-qualified URLs, and the hreflang side of this was fixed after Jul 26. Canonical was not, so the two are now inconsistent within the same <head>.

04

Fix 1 and 2: Open Graph and Twitter Card tags

Add to the shared metadata for every route, populated from data the page already has. In Next.js App Router this is the openGraph and twitter keys of the Metadata object, so it can be done once in the root layout and overridden per route.

Product pages, using existing listing fields:

<meta property="og:type"        content="product" />
<meta property="og:site_name"   content="Renter" />
<meta property="og:locale"      content="ar_SA" />   <!-- en_US on /en/ -->
<meta property="og:title"       content="{page title}" />
<meta property="og:description" content="{meta description}" />
<meta property="og:url"         content="https://renter.net{path}" />
<meta property="og:image"       content="https://renter.net{first listing image}" />
<meta property="og:image:width"  content="1200" />
<meta property="og:image:height" content="630" />

<meta name="twitter:card"        content="summary_large_image" />
<meta name="twitter:title"       content="{page title}" />
<meta name="twitter:description" content="{meta description}" />
<meta name="twitter:image"       content="https://renter.net{first listing image}" />

Notes that matter for rendering:

  • og:image must be an absolute URL. WhatsApp and Facebook will not resolve a relative path.
  • Use a site-wide fallback image for pages with no photo (info pages, categories, and the roughly 67 older listings with broken images) so no share renders blank.
  • Images should be at least 1200x630. WhatsApp additionally prefers files under about 300 KB, otherwise it often skips the preview.
05

Fix 3: structured data (JSON-LD)

Zero JSON-LD blocks exist today. Minimum useful set:

  • Product pages: Product with a nested Offer carrying price, priceCurrency: "SAR", availability and url.
  • Home page: Organization (legal name, logo, contact) plus WebSite with SearchAction.
  • Category and subcategory pages: BreadcrumbList.
  • FAQ page: FAQPage.
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "{listing title}",
  "description": "{meta description}",
  "image": ["https://renter.net{listing image}"],
  "url": "https://renter.net{path}",
  "offers": {
    "@type": "Offer",
    "price": "{price}",
    "priceCurrency": "SAR",
    "availability": "https://schema.org/InStock",
    "url": "https://renter.net{path}"
  }
}
</script>

One caution: only emit price when a real price exists. Some listings currently carry 0 SAR or a placeholder 1 SAR, and publishing those as schema prices would misrepresent the offer. Omit the Offer block rather than emit a placeholder.

06

Fix 4: absolute canonical URLs, and the two home pages have lost hreflang entirely

The hreflang half of this is already done, thank you. As of Aug 5 the alternate URLs are absolute on every page checked, so no further work is needed there. Two things in this section are still open.

4a. Canonical is still relative on all 12 pages. Currently served on /ar/properties/apartments/:

<link rel="canonical" href="/ar/properties/apartments/"/>      <!-- still relative -->
<link rel="alternate" hrefLang="ar" href="https://renter.net/ar/properties/apartments/"/>  <!-- fixed -->

Should be:

<link rel="canonical" href="https://renter.net/ar/properties/apartments/"/>

In Next.js this is what metadataBase is for: set it once to https://renter.net and the framework will emit absolute canonical URLs alongside the alternates it is already emitting correctly.

4b. New since Jul 26: /ar/ and /en/ emit no hreflang tags at all. Every other page on the site carries its three alternates (ar, en, x-default). The two home pages carry none. Verified Aug 5:

$ curl -s https://renter.net/ar/ | grep -c -i 'hreflang'
0
$ curl -s https://renter.net/en/ | grep -c -i 'hreflang'
0
$ curl -s https://renter.net/ar/aboutus/ | grep -c -i 'hreflang'
3

These are the two highest-traffic pages on the site, so they are the ones that most need the language pairing declared. Worth checking whether the home route bypasses the shared metadata helper that the other routes use.

Please re-run Ahrefs after the change to confirm the hreflang_issues flags are gone.

07

Fix 5: locale-less redirects should be 301, not 307

Locale-less paths currently redirect with a temporary status:

RequestStatus nowLocationShould be
https://renter.net/307/ar/301
https://renter.net/faq/307/ar/faq/301
https://renter.net/properties/apartments/307/ar/properties/apartments/301
https://renter.net/product/2097/10-ton-forklift/307/ar/product/2097/...301

A 307 tells Google the move is temporary, so it keeps the locale-less URL in its index and does not pass consolidated signals to the locale version. These are permanent routing decisions, so they should be 301. Note /ar and /en without the trailing slash already return 308 correctly, so this is specific to the locale-prefix redirect in middleware.

Scale of this one, measured in Search Console on Aug 5. Across every page that earned a click in the last 28 days, the locale-less addresses account for 261 of 457 clicks (57%) and 40% of impressions. The top two pages on the whole site by clicks, renter.net/ with 93 and /product/1228/myny-bystwn-ayjar-ywmy-wasbway/ with 62, are both on this path. That makes this the single highest-value item in the ticket: more than half the site's search traffic is currently landing on an address whose ranking credit is being held in limbo rather than passed to the page that actually serves it.

08

Bonus, same template layer: meta descriptions are double-encoded

HTML entities are being escaped twice, so the entity text renders literally inside the tag instead of the character it represents:

# /en/product/2168/sony-fx30/
<meta name="description" content="كميرا سوني fx30&amp;nbsp;">
                                                  ^^^^^^^^^^ renders as literal "&nbsp;"

# /en/product/1560/kryn50tn/  → &amp;quot; instead of a quote mark

Encode once. This is also why some descriptions look padded with stray characters in search results.

09

Acceptance criteria

  1. Every page returns a complete Open Graph set (og:title, og:description, og:image, og:url, og:type, og:site_name, og:locale) with an absolute og:image.
  2. Every page returns twitter:card, twitter:title, twitter:description and twitter:image.
  3. Pasting any product URL into WhatsApp renders a preview card with image and title.
  4. Product pages emit valid Product and Offer JSON-LD, passing Google's Rich Results Test with no errors, and no Offer is emitted for listings without a real price.
  5. Canonical href values are absolute and start with https://renter.net (the hreflang href values already are).
  6. /ar/ and /en/ each emit the same three hreflang alternates every other page emits.
  7. Ahrefs reports no hreflang_issues on the pages listed in section 03.
  8. curl -I on the locale-less URLs in section 07 returns 301.
  9. No meta description contains &amp; followed by an entity name.
