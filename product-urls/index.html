Product addresses: one official address per product, and "not found" for deleted products

NOT DONEChecked Oct 11, 2026: unchanged. Any slug still opens the product with its own canonical. Deleted products answer 307 to the home page: 99 of 1,188 addresses in the sitemap. Unknown category addresses now answer 404 correctly, so the same pattern works here.

In short

What is wrong (1)
A product page opens at any address that has its number. /ar/product/2545/kamyra-kanwn-4000d/, /ar/product/2545/4000d/ and /ar/product/2545/anything/ all show the same page, and each copy tells Google that it is the official address.
What is wrong (2)
When a product is deleted, its address sends the visitor to the home page. 99 of the 1,188 product addresses in the sitemap do this today (8%).
Why it matters
(1) Google can index several copies of one product and split its ranking between them. It already indexes two addresses for 11 products, for example /ar/product/1662/120/. (2) Google still lists deleted products as indexed (for example /ar/product/2797/, last crawled Sep 5). A searcher who clicks one lands on the home page with no explanation. Google calls a missing page that does not answer "not found" a soft 404, and the sitemap keeps sending Google to 99 dead addresses.
The fix
In the product page code: a product that does not exist answers 404 ("not found"). An address with any slug other than the official one moves permanently (308) to the official address. The canonical tag is built from the product data, never from the address that was typed. The sitemap lists live products only.
Owner
Dev team. The sitemap change goes to whoever builds /sitemap/ar/products.xml.
Done when
The 4 checks at the end of this page give the expected answers.

The fix: 4 changes

Code references come from the June copy of the repository, so read the changes as "replace this behavior". Good news from Oct 11: unknown category addresses such as /ar/properties/test/ now answer 404 correctly, so the same pattern works for products.

Change 1: one function for the official slug

Every place that builds a product address must use the same function: the sitemap, the product cards, the canonical tag, the hreflang tags, the JSON-LD url and offers.url, and the Merchant feed. The official slug is the one the sitemap and the product cards use today. Put that logic in one server-safe file (no 'use client'), for example src/lib/product-url.ts:

// The official slug of a product: the SAME value the sitemap uses today.
// Expected results (Oct 11):
//   2545 -> "kamyra-kanwn-4000d"
//   311  -> "frn-shwyh"
//   2822 -> "doosan-mega400v"
//   2830 -> "man-lft-jy-il-jy-mqas-22-mtr-manlift-jlg-22m"
export function productSlug(product: ViewPost): string {
  // Move here the code that builds the product slug for the sitemap today.
}

export function productPath(locale: string, product: ViewPost): string {
  return `/${locale}/product/${product.id}/${productSlug(product)}/`;
}

Do not use the new short slug in addresses. If the team wants short addresses one day, that is a planned move: every old address answers 308 to its new address, and the sitemap changes on the same day.

Change 2: the canonical tag comes from the product, not from the typed address

File: src/app/[locale]/product/[id]/[title]/page.tsx, function generateMetadata. The June code builds the canonical and hreflang tags from the address that was typed:

const path = `/product/${id}/${title}/`;

That is why any slug becomes its own "official" copy. Replace that line with this one, placed after the if (!product) check:

const path = `/product/${id}/${productSlug(product)}/`;

The rest of alternates (canonical, ar, en, x-default) stays as it is; it already uses path.

Change 3: 404 for missing products, 308 for wrong slugs

Same file, the page component. The June code sends a missing product to the home page:

if (!rawProduct) {
  return redirect("/");
}

Replace it with this block. Keep it in the same place, before anything else renders:

// Deleted or unknown product: answer 404 "not found".
if (!rawProduct) {
  notFound();
}

// Any slug other than the official one: move permanently (308).
const officialSlug = productSlug(rawProduct);
if (title !== officialSlug) {
  permanentRedirect(`/${locale}/product/${id}/${officialSlug}/`);
}

Read locale and title from params next to id: const { locale, id, title } = await params;. Change the import line to import { notFound, permanentRedirect } from "next/navigation";.

Add a friendly "not found" page so the visitor is not stuck: src/app/[locale]/not-found.tsx with a short message such as "هذا الإعلان لم يعد متاحًا" and links to the categories and the search. It keeps the 404 code.

Change 4: the sitemap lists live products only

/sitemap/ar/products.xml and /sitemap/en/products.xml list 99 deleted products each. Build them from the same rule the product page uses: if the page would answer 404, the product is not in the sitemap.
