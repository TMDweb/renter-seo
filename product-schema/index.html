Product schema: one field left, the main price

In short

What it is
Each product page carries a hidden code block (JSON-LD, schema type Product). It gives Google the product name, photos, price and address.
Done so far
Checked Oct 11 on all 1,061 live products: url, offers.url, name, description and sku are correct on 1,060. Good work.
What is wrong
One field: offers.price, the single main price Google shows in results. On 51 products with more than one lease term it is the first term's price, not the daily price.
Why it matters
Google shows this one number as the product price in search results. Product 2852 shows 10,500 (the monthly price) although it rents per day.
The fix
One rule in the template: offers.price = the daily price when a daily term exists, else the lowest price among the terms.
Owner
Dev team. Paulo and Jan decide who takes it.

/ar/product/311/frn-shwyh/ shows "price": 5 (its daily price), and the Rich Results Test shows no errors.

How to build every field (one template for all products)

JSON-LD fieldAPI sourceTransform
nametitleas is, trimmed
descriptiondescriptionstrip tags, decode all HTML codes, collapse spaces
imagepost_images[].imageall of them, in order (done)
skuidas a string (done)
url and offers.urlthe page canonicalthe same value in both, from productPath(locale, product)
offers.pricepost_lease_terms[] where type = "available"a JSON number: the daily price when a daily term exists, else the lowest price
offers.availabilityavailability_statusAVAILABLE to https://schema.org/InStock, UNAVAILABLE to https://schema.org/OutOfStock. Never drop offers
priceSpecification[]one entry per available lease termhourly HUR · daily DAY · weekly WEE · monthly MON · fixed no entry (done; keep it)
aggregateRating and reviewreview_summaryonly when review_count is 1 or more; author is a {"@type": "Person", "name": …} object (done; keep it)

Do not add: brand or gtin (no source field; never guess them from the title), priceValidUntil (a past date hides the price), return or shipping fields. English pages: the same template with the /en/ canonical.

How to print the block (Next.js App Router)

Print it in the server component (page.tsx) as a plain <script> in the returned JSX. Not next/script, not the metadata export, never from useEffect. The block must show in view-source with JavaScript off. Use the shared JsonLd helper from the home page ticket, which escapes the text like this:

<script
  type="application/ld+json"
  dangerouslySetInnerHTML={{
    __html: JSON.stringify(jsonLd).replace(/</g, "\\u003c"),
  }}
/>

Build the object field by field and never write null (the Rich Results Test flags it as an error; a field left undefined is simply dropped). Reference: Next.js JSON-LD guide.
