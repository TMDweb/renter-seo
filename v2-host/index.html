v2.renter.net: a full copy of the site that Google indexes

DONEJan fixed it. Checked Nov 5, 2026: every v2.renter.net address answers a 301 to the same path on renter.net, including robots.txt over http and https. The certificate now covers v2.renter.net, valid until Feb 3, 2027. The 181 v2 pages should drop out of Google over the next weeks; Saiaf checks Search Console.

In short

What is wrong
The address v2.renter.net points to the same server as renter.net and shows the whole live site: home, products and blog. It is a second copy of renter.net that is open to Google.
Why it matters
Google sees two copies of every page and splits the ranking between them. On the product page we inspected, Google chose the v2 address as the official one and ignored our canonical tag. Visitors who click a v2 result also get a browser security warning, because the certificate only covers renter.net.
The fix
Send every v2.renter.net address to the same address on renter.net with a permanent 301 redirect, at the server level.
Owner
Jan (server). Saiaf requests removal in Search Console after the redirect is live.
Done when
The 4 checks at the end pass.

Verified, Nov 5, 2026

All 4 checks pass:

  2. https://v2.renter.net/en/product/1876/bwklynat-liyjar/ answers 301 to the same path on renter.net. Query strings are kept.

The fix

The redirect has to keep the path, so each v2 page lands on its own renter.net page and keeps its ranking. In nginx, as a separate server block for the v2 host:

server {
    listen 80;
    listen 443 ssl;
    server_name v2.renter.net;
    # a certificate that covers v2.renter.net is needed for the 443 block
    return 301 https://renter.net$request_uri;
}

Three rules for this fix:

  • Do not block v2 in robots.txt first. If Google cannot crawl v2, it never sees the redirect, and the 181 pages stay in its index.
  • The certificate must cover v2.renter.net, or browsers and Google stop at the warning before they reach the redirect. A Let's Encrypt certificate for v2.renter.net is enough.
  • If v2.renter.net must stay a working site for the team, protect it with a password and send the header X-Robots-Tag: noindex instead. The redirect is still the better fix.
