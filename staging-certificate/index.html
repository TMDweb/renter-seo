NOT DONEChecked Sep 27, 2026: the security certificate of v2-staging.renter.net ended on Sep 23, 2026 and was not renewed. The live site renter.net is not affected.

Staging: the security certificate ran out on Sep 23

In short

What is staging
The test copy of the website, v2-staging.renter.net. Changes are checked there before they go to renter.net.
What is wrong
Every https site needs a security certificate (SSL): it gives the padlock and proves the site is real. Each certificate has an end date. The staging certificate was valid from Jun 25 to Sep 23, 2026, and nobody renewed it.
Why it matters
Since Sep 23, browsers show a full-page warning ("Your connection is not private") and block staging. Nobody can test there, so changes reach the live site untested. The English translation test is planned on staging first.
The live site
Not affected. The renter.net certificate renewed itself on Sep 23 and is valid until Dec 22, 2026.
The fix
Renew the staging certificate and repair its automatic renewal.
Owner
Whoever runs the staging server (dev team).
Done when
v2-staging.renter.net/ar/ opens with no warning, and the check at the end shows an end date in December 2026.

Proof, Sep 27

The certificate the staging server sends today:

issuer=C=US, O=Let's Encrypt, CN=YR1
subject=CN=v2-staging.renter.net
notBefore=Jun 25 01:16:41 2026 GMT
notAfter=Sep 23 01:16:40 2026 GMT

A strict https request fails (certificate check error 10, "certificate has expired"). The server is nginx. Port 80 answers and moves visitors to https, so Let's Encrypt can reach the server for the renewal check.

Why it stopped

Let's Encrypt certificates last 90 days. A renewal job on the server normally renews them 30 days before the end. The production server renewed on Sep 23; the staging server did not. So the renewal job on staging is missing or failing.

The fix

On the staging server, if it uses certbot (the usual Let's Encrypt tool with nginx):

# 1. See the certificate and its name
sudo certbot certificates

# 2. Renew it now
sudo certbot renew --cert-name v2-staging.renter.net

# 3. Load the new certificate
sudo systemctl reload nginx

# 4. Prove that the automatic renewal works
sudo certbot renew --dry-run
systemctl list-timers | grep certbot

# If step 2 fails, the reason is here
sudo tail -50 /var/log/letsencrypt/letsencrypt.log

If certbot certificates shows another name, use that name in step 2. If the server uses a different tool (acme.sh, a hosting panel), run that tool's renew command for v2-staging.renter.net, then make sure its scheduled job runs.

Done when

echo | openssl s_client -connect v2-staging.renter.net:443 -servername v2-staging.renter.net 2>/dev/null | openssl x509 -noout -enddate

Expected: notAfter= a date in December 2026. Then tell Saiaf; TMD re-checks staging and its noindex, nofollow tag.
