In short

What is wrong
The home page lost the code block that tells Google who runs the site: the name, the logo, the social accounts and the support contacts (schema types Organization and WebSite). The page now has only a product list block, and that list has 5 errors.

The fix
Part A: add back one identity block per language (complete code below). Part B: correct the product list (5 rules below). Both parts are in the home page server component.

Part A: the identity block (Organization and WebSite)

This block is new next to the product list. It does not replace it. One script per language. Checked Sep 27: the logo URL answers 200, the search URL /ar/search/?q= answers 200 with results, the social links are the ones in the site footer, and the phone and email are the ones on the return policy page.

export function homeIdentityLd(locale: "ar" | "en") {
  const ar = locale === "ar";
  return {
    "@context": "https://schema.org",
    "@graph": [
      ORGANIZATION,
      {
        "@type": "WebSite",
        "@id": `https://renter.net/${locale}/#website`,
        url: `https://renter.net/${locale}/`,
        name: ar ? "رينتر" : "Renter",
        alternateName: ar ? "Renter" : "رينتر",
        inLanguage: locale,
        publisher: { "@id": "https://renter.net/#organization" },
        potentialAction: {
          "@type": "SearchAction",
          target: {
            "@type": "EntryPoint",
            urlTemplate: `https://renter.net/${locale}/search/?q={search_term_string}`,
          },
          "query-input": "required name=search_term_string",
        },
      },
    ],
  };
}

Part B: the product list, 5 rules

  1. One script. Keep the CollectionPage with the list inside mainEntity. Delete the second, separate ItemList script.
  2. name = the page H1. Arabic: رينتر | منصة تأجير كل شي في السعودية | أجر واستأجر. English: Renter | Rent Anything in Saudi Arabia | Rent & Lease.
  3. url = the home page address, https://renter.net/ar/ or https://renter.net/en/, with one slash at the end.
  4. Each entry has "@type": "ListItem", position from 1, and url = the full product address. Use url, not item.
  5. The entries are all the product cards the server renders on the page, in display order, each product once (31 today).

The same two functions serve the home page and the 194 category and subcategory pages. Add them to src/lib/jsonld.tsx:

export function JsonLd({ data }: { data: object }) {
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{
        __html: JSON.stringify(data).replace(/</g, "\\u003c"),
      }}
    />
  );
}

export function collectionPageLd(name: string, pageUrl: string, productUrls: string[]) {
  const unique = Array.from(new Set(productUrls));
  return {
    "@context": "https://schema.org",
    "@type": "CollectionPage",
    name,
    url: pageUrl,
    mainEntity: {
      "@type": "ItemList",
      itemListElement: unique.map((url, i) => ({
        "@type": "ListItem",
        position: i + 1,
        url,
      })),
    },
  };
}

Use them in the home page server component (src/app/[locale]/page.tsx). h1Text is the text the page prints in its H1. productUrls are the full addresses of the product cards, in the order the page shows them:

<JsonLd data={homeIdentityLd(locale)} />
<JsonLd data={collectionPageLd(h1Text, `https://renter.net/${locale}/`, productUrls)} />
