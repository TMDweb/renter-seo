Category and subcategory pages: the ItemList block

This is the answer to the 3e question. The old ticket referenced code that did not exist; here it is, complete. Category and subcategory pages already carry a correct BreadcrumbList (verified Sep 5, 2026); keep it exactly as it is. What you ADD is one more script: a CollectionPage with an ItemList of the products shown on the page.

Honest expectation, so nobody chases a ghost: Google shows list rich results only for courses, movies, recipes and restaurants, so this block earns no visual change in Google. Its value is machine readability: it tells Google and AI crawlers exactly which products belong to which category. Low effort, keep expectations at zero visuals.

The pattern (Google's "summary page" carousel pattern)

  • One extra <script type="application/ld+json"> per category and subcategory page, next to the existing breadcrumb script.
  • name = the page H1. url = the page canonical.
  • itemListElement: one ListItem per product currently rendered on the page, in display order, with position and the absolute product url ONLY. No names, no prices, no Product objects inside the list; the product pages carry their own full Product block.
  • All URLs absolute, on renter.net, unique within the list.
  • The list changes when the page content changes; that is correct behaviour, render it from the same data that renders the grid.
  • English pages: identical, with the /en/ canonical and product URLs.

The variables (how to generalize to every category page)

JSON-LD fieldSource on the pageTransform
namethe page H1as is
urlthe page canonicalthe same function that fills rel="canonical"
itemListElementthe same product array that renders the gridone ListItem per product, position = display order starting at 1, url = absolute canonical product URL. Nothing else in the item

One template covers all 194 category and subcategory pages, both languages. No page needs manual work.

A subcategory page like /ar/cars-and-vehicles/cars/ gets the same block with its own H1, canonical, and its own product list.

How to render the block (Next.js App Router)

Render in the server component (page.tsx), as a native <script> in the returned JSX. Not next/script, not the metadata export, never from useEffect. The block must be visible in view-source with JavaScript off. Escape exactly like this, with one shared helper:

<script
  type="application/ld+json"
  dangerouslySetInnerHTML={{{{
    __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c'),
  }}}}
/>

Build the object conditionally; never emit null (it fails validation, while dropped undefined is safe). Reference: nextjs.org JSON-LD guide.
