Category and subcategory pages: the ItemList block, with infinite scroll

Rebuilt Sep 7, 2026 after the meeting question: "the schema is in a server component, but scroll adds products in a client component; how do we keep it complete?" The answer comes from Google's own documentation and it is simpler than feared: the block lists the server-rendered products only, and it must never be updated from the client. Completeness comes from paginated URLs, not from scroll.

Why, in Google's words

Google saysWhat it means for usSource
"Google Search does not interact with your page."Googlebot never scrolls. Products loaded on scroll do not exist for Google, so a client-side update to the JSON-LD would describe products Google cannot see.Lazy-loading content
"Google's crawlers don't 'click' buttons and generally don't trigger JavaScript functions that require user actions to update the current page contents."A "load more" button or scroll trigger is invisible to Google unless it is a real link.Pagination and incremental page loading
"Google Search can understand and process structured data that's available in the DOM when it renders the page."Only what the server renders is read reliably. Keep the block in the server component, as it is now.Structured data with JavaScript
"Your structured data must be a true representation of the page content." and "Don't mark up content that is not visible to readers of the page."The list must equal the products actually rendered in the initial HTML: not fewer, not more.Structured data policies
"Give each chunk its own persistent, unique URL", "using ?page=12", "Link sequentially to the individual URLs", "give each page its own canonical URL."If every product must be reachable through category pages, add paginated URLs. Each one is server-rendered with its own product set and its own ItemList.Both docs above

Also true, and it lowers the stakes: every product page already carries its own Product block and is in the sitemap and the Merchant feed. The category ItemList is a map, not the only road. Google shows list rich results only for courses, movies, recipes and restaurants, so this block earns no visual change; its value is machine readability.

What to build (two parts)

Part 1, required now: the block for the first page

  • One extra <script type="application/ld+json"> per category and subcategory page, next to the existing breadcrumb script. Rendered in the server component from the same product array that renders the first grid. Never touched by the client component; infinite scroll changes the grid, not the script.
  • name = the page H1. url = the page canonical. itemListElement = one ListItem per server-rendered product, position from 1, absolute product url only. Nothing else in the item.
  • Same template for English pages with the /en/ canonical.

Part 2, recommended, when convenient: paginated URLs

  • Serve /ar/cars-and-vehicles/?page=2, ?page=3 and so on from the server with the next set of products, each with its own H1, its own self-referencing canonical (?page=2 canonical is ?page=2, not page 1) and its own ItemList of that page's products.
  • Add a real <a href="…?page=2"> link at the end of the grid (it can be the "load more" control itself). Keep infinite scroll for users and update the address bar with the History API, as Google's doc describes.
  • Do not use rel="next"/"prev"; Google no longer reads them.

How to render the block (Next.js App Router)

Render in the server component (page.tsx), as a native <script> in the returned JSX. Not next/script, not the metadata export, never from useEffect. The block must be visible in view-source with JavaScript off. Escape exactly like this, with one shared helper:

<script
  type="application/ld+json"
  dangerouslySetInnerHTML={{{{
    __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c'),
  }}}}
/>

Build the object conditionally; never emit null (it fails validation, while dropped undefined is safe). Reference: nextjs.org JSON-LD guide.

Definition of done

  1. View-source with JavaScript off shows two scripts (breadcrumb + this block) on /ar/cars-and-vehicles/ and /ar/cars-and-vehicles/cars/.
  2. The URLs in the list equal the products in the initial server HTML, same count, same order.
  3. Scrolling adds products to the grid and does not change the script (check the DOM after scrolling).
  4. validator.schema.org reports zero errors.
  5. Ping Saiaf on deploy.
