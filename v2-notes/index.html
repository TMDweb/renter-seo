TL;DR. The V1 SEO work documented in Renter — Needed From Dev Team (V1 punch list) has not been ported to V2. Most line items we closed or partially closed in V1 are not present in V2's server-rendered HTML. 1. Critical: V2 staging is crawlable #

Before any other discussion, this needs to ship today. The Feb 5 staging protection we agreed to is not in effect.

Link: rel="alternate" hreflang=… HTTP header Should not be sent on staging Sent on every page, pointing to v2-staging.renter.net URLs Active SEO leak

Why this is urgent. If Google crawls V2 staging before production cut-over, it has two near-identical Renter sites to choose from. The hreflang headers being emitted from staging tell Google these are the canonical international versions of this content, which can cannibalise V1 rankings we have spent months building.

3. Evidence — what I checked and what I saw #

All checks were run against the public staging site on 2026-05-06. Anyone on the team can re-run them from their terminal.

3.1 SEO meta is empty on every page

I fetched the SSR HTML of /en/, /ar/, a product page, and a category page. All four returned:

<title>Renter</title>
<meta name="description" content="Renter Description">
<!-- no <link rel="canonical"> -->
<!-- no <link rel="alternate" hreflang="..."> -->
<!-- no <meta name="robots"> -->
<!-- no <script type="application/ld+json"> -->
<!-- no <h1> tag anywhere in the document -->

3.2 robots.txt does not exist as a file

$ curl -sI https://v2-staging.renter.net/robots.txt
HTTP/2 200
content-type: text/html; charset=utf-8
x-powered-by: Next.js

The route is being caught by the Next.js SPA fallback. The response body is the homepage HTML, with the funny giveaway that <html lang="robots.txt"> — the path is being passed in as the lang attribute. Same behaviour for /sitemap.xml.

3.3 Hreflang HTTP headers are leaking staging URLs to Google

$ curl -sI https://v2-staging.renter.net/en/ | grep -i '^link:'
link: <https://v2-staging.renter.net/en/>; rel="alternate"; hreflang="en",
      <https://v2-staging.renter.net/ar/>; rel="alternate"; hreflang="ar",
      <https://v2-staging.renter.net/>;    rel="alternate"; hreflang="x-default"

These headers should not be emitted on the staging hostname at all. They tell search engines the staging URLs are valid international alternates of each other.

3.4 What V2 got right

  • <html lang> and dir are correct per locale (en/ltr, ar/rtl).
  • Viewport is set without maximum-scale.
  • Trailing slashes are consistent on internal links and product URLs.
  • Category cards are wrapped in <a> to category pages.
  • SSR is in place — the HTML is being rendered on the server, not by the client.

4. Action plan for dev (in priority order) #

P0 — Block staging from search engines (today)

Three small changes; ship all three.

P0-1 · Real robots.txt in Next.js

If you are on the App Router, create app/robots.ts:

import type { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return { rules: [{ userAgent: '*', disallow: '/' }] }
}

If on the Pages Router, drop public/robots.txt:

User-agent: *
Disallow: /

Either way, curl -I /robots.txt should return Content-Type: text/plain.

P0-2 · nginx X-Robots-Tag header on the staging host (belt-and-suspenders) 
server {
  server_name v2-staging.renter.net;
  ...
  add_header X-Robots-Tag "noindex, nofollow, noarchive" always;
}

This protects every response — HTML, JSON, images — regardless of whether the app outputs the right meta tag.

P0-3 · Stop emitting Link: rel="alternate" hreflang" headers on staging

Either gate header emission on environment in the app:

if (process.env.NEXT_PUBLIC_ENV === 'production') {
  // emit hreflang Link headers
}

Or strip them at the edge for the staging host:

server {
  server_name v2-staging.renter.net;
  proxy_hide_header Link;
}
P0-4 · Recommended: HTTP basic auth on staging (nginx) 
server {
  server_name v2-staging.renter.net;
  auth_basic "Renter Staging";
  auth_basic_user_file /etc/nginx/.htpasswd-staging;
}

Best long-term protection — blocks crawlers, leaks, and casual visitors. Should be added regardless of the three steps above.

P1 — Wire SEO metadata in the Next.js layout / per-route

Each route needs unique title, description, canonical, alternate (hreflang), and an h1. In App Router this is the generateMetadata() function plus <h1> in the page component. 

// app/[lang]/product/[id]/[slug]/page.tsx
import type { Metadata } from 'next'

export async function generateMetadata({ params }): Promise<Metadata> {
  const product = await getProduct(params.id)
  const path = `/product/${params.id}/${params.slug}/`

  return {
    title: `${product.name} — Renter`,
    description: product.shortDescription.slice(0, 155),
    alternates: {
      canonical: `https://renter.net/${params.lang}${path}`,
      languages: {
        en: `https://renter.net/en${path}`,
        ar: `https://renter.net/ar${path}`,
        'x-default': `https://renter.net${path}`,
      },
    },
    openGraph: {
      title: `${product.name} — Renter`,
      description: product.shortDescription.slice(0, 155),
      images: [product.coverImage],
      locale: params.lang,
    },
    robots: { index: true, follow: true },
  }
}

Apply the same pattern to homepage, category pages, lessor profiles, and the static info pages once they exist.

P2 — JSON-LD product schema

Inject Product + Offer + AggregateRating JSON-LD on each product page (server-rendered, not via client JS).

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Tool Kit",
  "description": "...",
  "image": "https://...",
  "offers": {
    "@type": "Offer",
    "priceCurrency": "SAR",
    "price": "100",
    "availability": "https://schema.org/InStock"
  }
}
</script>

P3 — Real /sitemap.xml

App Router supports app/sitemap.ts exporting a function that returns the URL list. Should resolve dynamic listing IDs and include lastModified per URL.

P4 — Restore the legal/info pages and the Help section

  • Build real routes (not href="/en/" placeholders) for: Contact Us, FAQ, About Us, Terms & Conditions, Cancellation Policy, Privacy Policy.
  • Integrate the Help Center prototype Saiaf shipped on Feb 19 at /help/.
  • Add About Us and Help to the global nav (V1 step 22).

P5 — Single <h1> per page

Convention: h1 = page/listing title. One H1 per page across homepage, category, product, lessor, and info pages.

5. How to verify each fix #

Once dev says a fix is live, anyone on the team can run these from a terminal. If the output doesn't match, the fix isn't actually live.

5.1 Crawler protection

# Should print: X-Robots-Tag: noindex, nofollow, noarchive
curl -sI https://v2-staging.renter.net/en/ | grep -i x-robots-tag

# Content-Type must be text/plain, body must be exactly the Disallow rule
curl -sI https://v2-staging.renter.net/robots.txt | grep -i content-type
curl -s  https://v2-staging.renter.net/robots.txt

# Should print NOTHING (Link headers stripped on staging)
curl -sI https://v2-staging.renter.net/en/ | grep -i '^link:'

5.2 SEO metadata

# Each URL should return a different title and description
for url in /en/ /ar/ /en/properties/ /en/product/2/tool-kit-adh-adwat/ ; do
  echo "=== $url ==="
  curl -s "https://v2-staging.renter.net$url" \
    | grep -oE '<(title|meta name="description"|link rel="canonical"|link rel="alternate")[^>]*>'
done

Appendix A — Non-SEO issues spotted on V2 #

Out of scope for the SEO punch list, but flagged here so they are not lost. These are observations from a 10-minute click-through of staging on 2026-05-06.

A.1 Pages that exist as links but not as pages (KSA legal/UX blocker)

Every footer link in Info & Support currently points to /en/:

  • Contact Us
  • Frequently Asked Question
  • About Us
  • Terms and Conditions
  • Cancellation Policy
  • Privacy Policy

For a Saudi marketplace these are not optional — Terms, Privacy, and Cancellation Policy are regulatory.

A.2 Test/dummy data is publicly visible

The "Popular" carousel on the homepage is rendering obvious test rows that should not ship to production:

  • Test
  • Shy
  • Test Prod Hourly Daily
  • Daily + Hourly QTY 1
  • NDB - Hourly & Daily Only
  • Product For new Database Design
  • Kim-Case 17-New
  • Renter Test Post 2
  • NewDB Test product
  • case 8, Drop Off Product

Several listings also have empty price values rendered as /Day with no number.

A.3 Reviews are placeholder copy from a different template

The Tool Kit product page (/en/product/2/tool-kit-adh-adwat/) shows four reviews, all from "Mohamad Adnan" dated 2025-10-05, all describing villas, pools, and Riyadh stays. These appear to be lorem-ipsum review copy from a property-rental template that was never replaced.

A.4 UI bugs and broken links

  • Product page rating renders 4.9 [object Object] — unrendered JS object exposed.
  • Product page map stuck on "Loading map…".
  • Show All link → href="#".
  • Show all reviews → /en/my-reviews/ (the user's own reviews page, not the product reviews).
  • No global header / nav / search / login / signup visible.
  • No date picker on product pages — booking flow can't be exercised.

A.5 Bilingual data quality

Product names mix English and Arabic awkwardly inside a single string:

  • Tool kit عدة أدوات
  • Haam Electric ثلاجة

Should be split into separate name_en / name_ar fields and rendered per locale.

A.6 Page weight

The homepage HTML response alone is 589 KB. Full page weight (with assets) needs to be measured against the < 3 MB target from V1.
