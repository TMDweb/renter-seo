Fix 2: never return an empty file (open)

Feed files intermittently return a valid RSS shell with zero items and HTTP 200 (reproduced again Sep 5: feed-24 returned 0 items in one run and 50 in another). Merchant Center accepts the empty file and silently drops those 50 products for the day; this is what emptied Google Shopping on Aug 25. Required behaviour: when product data cannot be fetched, return HTTP 500, never an empty 200, and log the failure. Merchant Center then keeps the last good version instead of deleting the products.

All files were empty again between Oct 5 and Oct 13, and again on Oct 18. The feed was full again on Oct 25 and on Nov 1. Also add an alert when file 1 has 0 products. Check: curl -s https://renter.net/merchant-feed-1.xml | grep -c '<item>' must print 50.
