1. Why this ticket exists #

We ran a manual test: a Merchant Center account with only 10 products added by hand. Result, without any ad spend:

79
Organic clicks from Google Shopping
7 / 10
Test products that received clicks
938
Active products live today (per sitemap)

Scaling this to the full catalog needs a data feed, not manual entry. This is separate from the XML sitemap: the sitemap tells Google which pages exist, the merchant feed carries structured product data (price, availability, images) for Shopping listings, and later enables paid Shopping campaigns.

2. Approach #

Same pattern as the sitemap route: one new App Router route that renders XML straight from the products API. 

src/app/merchant-feed-ar.xml/route.ts   →   https://renter.net/merchant-feed-ar.xml
  • Include all active products, pulled live from the same data source the sitemap uses.
  • Regenerate automatically on a cache window: a 1 to 6 hour revalidation (like the sitemap's 6-hour refresh) is fine.
  • Saiaf registers the URL in Merchant Center as a scheduled daily fetch. Products added or removed by lessors flow in and out automatically, no manual sync ever.
  • Start with one Arabic feed (content language ar, target country SA). An English feed can be added later as a second file.

Out of scope for this ticket (phase 2)

Real-time push updates via the Content API for Shopping. Not needed for launch, the daily scheduled fetch plus the auto-regenerating feed is the standard setup.

3. Spec: required fields per product #

AttributeValue for RenterNotes
g:id Numeric product ID, e.g. 2213 Must be stable, never reused
g:title Product name (AR) Max 150 characters
g:description Product description, plain text Strip HTML
g:link https://renter.net/ar/product/{id}/{slug}/ Final URL with trailing slash, must return 200 directly, no redirect hop
g:image_link Main product image URL Min 250x250 px, no watermarks. Extra images via g:additional_image_link, up to 10, one tag each
g:availability in_stock / out_of_stock Drive from real product status
g:price e.g. 150.00 SAR Must match the price shown on the page. Mismatch is the #1 disapproval reason. If price varies by duration, use the base price visible on the landing page
g:condition used Rentals are generally "used", new only where truly new
g:identifier_exists false Rental items have no GTIN/MPN, this prevents disapprovals. g:brand optional when this is false
g:product_type Renter category path, e.g. أزياء وملابس > فساتين Helps Google classify the product

4. Feed template (RSS 2.0 with the Google namespace) #

<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0" xmlns:g="http://base.google.com/ns/1.0">
  <channel>
    <title>Renter</title>
    <link>https://renter.net/ar/</link>
    <description>Renter product feed</description>

    <item>
      <g:id>2213</g:id>
      <g:title>فستان ناعم</g:title>
      <g:description>فستان ناعم للإيجار، يلبس سمول، بحالة ممتازة.</g:description>
      <g:link>https://renter.net/ar/product/2213/fstan-naam/</g:link>
      <g:image_link>https://renter.net/images/products/2213/main.jpg</g:image_link>
      <g:availability>in_stock</g:availability>
      <g:price>150.00 SAR</g:price>
      <g:condition>used</g:condition>
      <g:identifier_exists>false</g:identifier_exists>
      <g:product_type>أزياء وملابس &gt; فساتين</g:product_type>
    </item>

  </channel>
</rss>

One <item> per active product. Escape XML entities in titles and descriptions.

5. Acceptance criteria #

  • https://renter.net/merchant-feed-ar.xml returns valid XML containing every active product.
  • Every g:link returns 200 directly (trailing slash included, no redirect hop).
  • A product removed by a lessor disappears from the feed within the refresh window; a newly added product appears within the same window.
  • Prices in the feed match the product pages exactly.
  • Feed validates in Merchant Center's feed upload with zero critical (item-level policy disapprovals are expected and handled by Saiaf).
